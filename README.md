# kiro-community-worker

> ⚠️ Unofficial project
>
> Project status: Experimental

Cloudflare Worker for Kiro Community Repository.

This Worker provides a single public endpoint for the repository by:

- proxying repository metadata from GitHub Pages;
- redirecting package downloads to the official Kiro distribution servers;
- avoiding redistribution of Kiro binaries.

> This is an unofficial community project and is not affiliated with AWS or the Kiro team.

## Architecture

```text
APT Client
    |
    v
repo.kiro-community.dev
    |
    +--> GitHub Pages
    |     ├── dists/
    |     ├── public/pubkey.asc
    |     ├── KEYS
    |     └── index.html
    |
    +--> Redirects /pool/*
          |
          v
     Official Kiro servers
```

## How it works

Repository metadata is served from:

```text
https://giovannimet.github.io/kiro-community-repo
```

Package downloads are redirected to the official Kiro download infrastructure.

The Worker reads the package mapping generated by the repository automation and performs a temporary redirect when a package is requested.

Example:

```text
/pool/main/k/kiro/kiro-ide-1.4.13-stable-linux-x64.deb
```

becomes:

```text
https://prod.download.desktop.kiro.dev/releases/stable/linux-x64/signed/1.4.13/deb/kiro-ide-1.4.13-stable-linux-x64.deb
```

## Design Goals

- Single public repository endpoint
- No package redistribution
- Signed repository metadata
- Automatic package updates
- Minimal operational overhead
- Low bandwidth consumption
- Compatibility with standard Debian APT clients

## Deployment

The Worker is configured with `repo.giovannimetitieri.it` as a Cloudflare Custom
Domain. The domain must be an active zone in your Cloudflare account, and it
must not already have a conflicting DNS record. Wrangler creates the DNS record
and certificate when you deploy.

### Automatic deployment

The GitHub Actions workflow validates the Wrangler configuration and deploys the
Worker on every push to `main`.

Add these repository secrets in **Settings > Secrets and variables > Actions**:

- `CF_API_TOKEN`: a Cloudflare API token allowed to deploy Workers and configure
  the custom domain/DNS record.
- `CF_ACCOUNT_ID`: the Cloudflare account ID that owns the Worker and zone.

Keep `wrangler.toml` as the source of truth for deployable Worker settings. The
Worker already sets cache lifetimes on its responses; Workers Cache behavior is
driven by those response headers and does not require a separate Wrangler
setting.

### Local development and manual deployment

```bash
npm install
```

Authenticate with Cloudflare:

```bash
npx wrangler login
```

Run locally:

```bash
npx wrangler dev
```

Deploy:

```bash
npx wrangler deploy
```

## Repository Relationship

This repository works together with:

- kiro-community-repo

The repository project:

- discovers new Kiro releases;
- generates APT metadata;
- signs repository indexes;
- publishes metadata to GitHub Pages.

This Worker:

- exposes a single repository endpoint;
- caches metadata requests;
- redirects package downloads to official Kiro infrastructure.

## Security

The Worker never stores, modifies or redistributes Kiro binaries.

Repository metadata remains signed using the Kiro Community Repository GPG key.

Package binaries are downloaded directly from official Kiro distribution servers.
